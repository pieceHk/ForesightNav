## 1. 目标、现状判断与不变量

### 1.1 目标

在不改变 3-MON 的 ordered target sequence、不使用 semantic ground truth 的前提下，利用 episode 初始化时已经可见的完整剩余目标序列，对当前候选选择加入 ordered suffix route cost，使当前成功位置更有利于后续目标，从而提升 Episode SPL 与 PeSPL；SR 与 PSR 不得下降。

计划只优化“选择哪个已检索 candidate/verification waypoint，以及何时安全地采用该选择”。不改目标顺序，不让 map score 直接完成目标；subtask 仍只能由现有 local verifier 确认后推进。

### 1.2 基线代码已经提供的支点

- `Navigation/runtime/evaluators/goat/entrypoint.py` 在首帧读取完整 `obs.task_observations["tasks"]`，3-MON 的三个 ordered subtasks 在 episode 开始即已知。
- GOAT `OnlineESProvider.get_all_goals()` 已对全部剩余类别做 `batch_query`；mapper response 已包含 `candidate_records_by_category`，record 中已有 `position/raw_rank/semantic_score/support_count/support_score/map_revision`。
- single-target HM3Dv1 provider 已实现 candidate-record cache 与 alignment，可作为 GOAT port 的参考；GOAT provider 尚未消费该 sidecar。
- “设想 1”的 `CandidateActionReranker` 已有 semantic/support/recurrence/current travel/novelty/revisit/failure 与 hysteresis，但这些都是 deterministic utility components，不是概率。GOAT runtime 目前没有完整接入这条 metadata-aware rerank path。
- `last_fused_keyframes` / `map_revision` 可支撑 MVP 级 version token；当前代码还不具备 design draft 所述的原子 map snapshot、稳定 Gaussian identity 与 witness replay ledger。
- `mon_metrics_v3` 已记录并校验 SR/SPL/PSR/PeSPL、actual/shortest path length、steps、frame timing；其结果只能用于 evaluation/telemetry，绝不能回流到 policy。

### 1.3 全程不变量

1. 数据固定为 `/data/3DONav_datasets/HM3Dv1_MON_balanced1200_v1_runtime_compat_20260829/3MON_400x3`；每个完整 episode 必须恰有 3 个 ordered subtasks。
2. 所有实验只用 `--gpus 4,5`：GPU 4 运行 mapping，GPU 5 运行 navigation；不得自动换卡。
3. `semantic_source="detic"`、LagMemo `GROUND_TRUTH_SEMANTICS=0`；禁止读取 simulator semantic scene、goal viewpoints、GT object position 或 success oracle 来生成候选、排序、规划、阈值或在线 fallback。
4. `per_keyframe_snapshots=false`、`PRINT_IMAGES=0`；不保存 per-frame images。允许结构化 JSON/JSONL/CSV telemetry 与最终 aggregate。
5. baseline executable 的 `git_head` 必须等于完整 SHA `474a752a22867b4af34812bf12c50c8019872fcc`。不得用“关闭新 flag 的新代码”冒充 exact baseline。
6. treatment 与 baseline 必须匹配 dataset manifest/hash、episode identities/order、seed、top-k、refresh cadence、max steps、verification、cooldown、mapping 与 navigation 配置；只有预注册的 arm 差异可以不同。
7. 每个 episode identity 固定为 `(dataset_manifest_sha256, scene_id, runtime_episode_id, source_episode_id, ordered_categories)`；paired analysis 只能按完整 identity inner join，缺失、重复、顺序变化都 fail closed。
8. 原始 CLIP/SEEM/semantic/support/rerank score 只称 `score` 或 `heuristic utility`，禁止命名为 `probability/confidence/posterior/likelihood`。未经独立 calibration 的数值不得进入期望代价 Bellman backup。
9. `positive` 仅指现有 local verifier 已确认；MVP 中 verification 失败、视野外、遮挡、深度无效、候选消失均记为 `unknown`。没有 certified geometry rule 时不得产生 `certified_negative` 或据此删除候选。
10. suffix planner 缺 record、版本混合、无可达 edge、status 过期或计算异常时，保持当前 baseline/Idea-1 order，不做 suffix intervention；不得用 Euclidean distance 悄悄替代不可用的 geodesic distance。

## 2. MVP contract 与算法边界

### 2.1 MVP 数据合同

新增 model-independent contracts（名称可在 Batch 0 内微调，但字段语义不得改变）：

- `CandidateRecord`：`task_idx/category/position/raw_rank/semantic_score/support_count/support_score/map_revision`；candidate identity 为 episode、task、revision 内的 `(raw_rank, quantized_xyz)`，不宣称跨 revision 稳定。
- `CandidateBatch`：完整 ordered categories、每个 task 的 aligned records、`scene_id/episode_id/map_revision/last_fused_keyframes/query_serial` 与 validation status。
- `SuffixPlan`：输入 version token、current task、strict geodesic matrix、每个 current candidate 的 suffix cost、selected raw rank、fallback/intervention reason、compute time。
- `EvidenceState` 预留 `verified_positive/certified_negative/unknown`；MVP producer 只能输出 `verified_positive` 或 `unknown`。

所有合同必须拒绝 NaN/Inf、错维 position、重复 task index、record/position 数量错位与 mixed revisions。不可达 geodesic 在内存中可用 `inf` 计算，但 JSON 中必须编码为 `null` 加显式 status。

### 2.2 MVP suffix heuristic

对当前目标索引 `k` 和每个 task 的有限候选集 `C_r`，用 Habitat pathfinder 产生 strict geodesic edge `d_v(i,j)`。纯函数做 reverse min-plus DP：

```text
F_last(i) = 0
F_r(i) = min over j in C_(r+1) of [d_v(i,j) + F_(r+1)(j)]
```

当前 candidate `i` 的 suffix component 为 `F_k(i)`。先按设想 1 的现有 deterministic utility 得到 `U_idea1(i)`，再计算：

```text
U_mvp(i) = U_idea1(i) - suffix_weight * normalize_finite(F_k(i))
```

约束如下：

- `suffix_weight` 预注册为 `0.35`，与现有 current-travel weight 同量级；frozen gate 前不得按结果调参。
- 每层最多取设想 1 顺序的前 `K=5` 个候选；3-MON 最多两层 suffix，规模有界。
- normalization 仅在同一 current-task candidate set 内做，仍是 heuristic，不是 metres/probability 的混合解释。
- stable tie-break 固定为 `(idea1_order, raw_rank, xyz)`；相同输入必须 bitwise-stable 地产生同一顺序。
- 当前 task 已是最后一个、任一必需 future layer 为空、所有 edge 不可达、version 无效，或 suffix scores 全相同，则 `intervention=false` 并保留设想 1 顺序。
- MVP 的 success suffix 只是假设“选中候选经 local verifier 成功后的路线摘要”；它不声称估计 candidate truth probability，也不展开失败/未知分支。

### 2.3 Version safety 的 MVP 范围

- query response 的 records 与 coordinates 必须在同一 response 中原子取得，并形成 `(last_fused_keyframes, query_serial)` token。
- plan cache key 必须包含 episode identity、current task、ordered category tuple、map revision 与所有 candidate identities；任一变化即整体失效。
- dispatch 前读取 mapper `status`。`rebuilding=true`、episode 不匹配、`last_fused_keyframes != plan.map_revision` 或 provider token 已变化时，不得派发该 suffix-induced switch；同步 re-query/replan，一次失败后回到非 suffix order并记录原因。
- 这只保证“SCSP decision 不跨已观测到的 mapper revision”；原子 Gaussian snapshot、历史 witness 重投影及跨 revision stable object identity 延期。

### 2.4 设计稿能力拆分

| 能力 | MVP | 延期条件 |
|---|---|---|
| 完整 ordered suffix | 用现有 candidate waypoints + strict geodesic reverse DP | 多 verification views 与 exploration continuation cost 延期 |
| 三态 evidence | 仅 `verified_positive` 与保守 `unknown`；schema 预留 negative | 需 3DGS render depth/first-hit visibility、实测 depth 对齐、投影尺度与独立阈值验证后才允许 `certified_negative` |
| 概率 calibration | 不进入；所有 score 明示 heuristic | 需与 navigation evaluation 完全隔离的 calibration split、冻结模型，并报告 Brier/NLL/ECE/coverage 与 OOD abstention |
| contingent branches | 不进入；MVP 不做 expected Bellman backup | 只有 calibrated `p+/p-/p?` 与可信 transition 后才实现；否则最多做不依赖概率的 worst-case bound research |
| version safety | query/status revision token、cache invalidation、dispatch gate | 原子 snapshot publication、witness ledger、reprojection 与 stable identity 属 mapper architecture 后续工作 |
| verification pose set | 使用现有 projected waypoint 与 local verifier | GOAT 可达 observation ring、朝向与 sightline utility 要有独立 geometry contract 后再接入 |

延期能力不得为了“贴合论文公式”混入 MVP。每项后续能力都需独立 branch/proposal、独立 tests 与新的 paired gate，不能在本计划的 frozen evaluation 中临时打开。

**预设 go/no-go gates（全部满足才 GO）**

- Integrity：A/B/C identity inner join 为 48/48，全部 complete；0 GT access、0 image artifact、0 stale suffix dispatch、0 non-strict JSON。

- Efficiency：`SPL_C - SPL_A >= 0.01`、`PeSPL_C - PeSPL_A >= 0.01`，且 PeSPL 的单侧 90% lower bound `> 0`。

- Runtime：C 相对 B 的 mean frame-time overhead `<= 5%`、p95 overhead `<= 10%`；suffix planner p95 `<= 20 ms`，无持续 cache growth。

## 5. 延期 research tracks（不计入当前 8 个 Batch）

### D1 — Certified tri-state sightline evidence

只有 D1/D2 均通过，才实现 `positive/certified_negative/unknown` transitions、Bayesian update 与 contingent backup；negative 与 unknown 必须从实际到达 verification pose 继续并支付 recovery cost。ambiguity set 的构造也必须由 held-out calibration evidence 支持。该 track 需要新的 branch、contracts、frozen paired manifest 与完整 gates，不能追溯性改写 MVP 结论。
