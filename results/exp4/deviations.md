# Exp4 差异与处理记录

| 位置 | 设计规定 | 实际做法 | 原因与影响 |
| --- | --- | --- | --- |
| 代码基线 | 以服务器工作区为最新版本 | 从服务器 HEAD `ef9ecd7` 叠加其全部现有代码修改，提交为 `7c7e9f4`；实验在独立目录 `/nvme/khy/ForesightNav_exp4` 和分支 `exp4/blp-eq13` 开展 | 保留服务器尚未提交的优化和 MFMON 接口；原工作区供其他实验继续使用 |
| E 与 Eq.(5) | 使用 `CandidateRecord.semantic_score`，核查是否为支撑集均值 | 保留该字段；它是所选高斯的 codebook 加权文本相似度，不是邻近支撑高斯的均值 | 用户已确认保留 E、调整论文描述；查询引擎和旧模式排序不变 |
| S | 优先低成本高斯级，否则使用候选级 | 使用 `CandidateEvidenceBank` 空间轨迹的 12 位方位掩码；跨目标重置仅保留覆盖掩码，旧 recurrence 计数仍按原逻辑清空 | 未给建图进程增加逐高斯观测传输；覆盖状态不参与旧模式排序 |
| Frontier | 当前导航地图转世界坐标 | 使用最近一次导航调用生成的 frontier map，反变换到世界坐标并投影到 navmesh；相对于当前 RGB-D 最多滞后一帧 | 规划发生在本帧原生导航建图之前；首个快照没有 frontier 时使用设计规定的无坐标退化，不额外调用导航建图 |
| 影子 C_exp | 临时给定 a、b0、pi，未指定临时 C_exp | 管线验证暂用 `C_exp=10 m`，日志保存此值；正式 C_exp 仅由空候选激活事件的路径均值拟合 | 此值只用于影子计算，不用于评估，也未按评估成绩选择 |
| Nearest 的偏离率 | 同时要求四个变体采用 1 m 滞回/类别冷却，且 Nearest 偏离率恒为 0 | 实现共享滞回和冷却；区分无约束 proposal、滞回后排序、最终实际下发的候选 | 用户已确认保留共享机制、分开报告；实际 Nearest 可能暂时保留较远候选 |
| 回归方式 | 三个固定 episode 的逐步决策保持一致 | 从原版真实运行逐次保存 planner 输入、reranker 状态和所有测地查询结果，供修改后的关闭模式逐次重放，比较除耗时外全部值和排列 | 避免独立 GPU 仿真运行的随机差异掩盖代码回归；明确属于相同输入的逐步回归 |
| 管线试跑 | 正式标定前验证输入和日志 | 固定 2-MON `6s7QHgap2fW/0` 做两次管线试跑；第二次补齐候选坐标 GT 标签和包含接近路径的访问开销 | 两次均保留，不进入最终标定拟合；两次 48 步轨迹完全一致，没有据此调节算法超参数 |
| 诊断真值 y | 按评估器成功判据标注候选 | 复制原 GOAT distance/success measures，用只读模拟器代理代入候选坐标，调用原计算函数；另保留 agent 检查时标签 | 候选位置与验证时 agent 位置可不同；不移动真实 agent，不修改真实测量或目标顺序，真值不进入 planner |
| GPU 释放 | 终止 GPU 2、3 上的任务 | 对这两卡查询到的四个 PID 发送 SIGTERM，确认退出后启动本实验 | 一进程同时使用 GPU 0、3；对该进程的终止也减少了 GPU 0 占用。未终止其他 GPU 上的独立进程 |
| 非查询点的验证 | 对候选验证事件记录 E 并标定 | 导航脱困临时 waypoint 单独记为 `noncandidate_verification`，保留 v/GT，但不进入候选 belief 拟合；仍被冷却保留的旧查询候选使用有来源记录的历史 E | 临时脱困点不存在查询 E，不能编造分数或错误归给附近候选。按来源分类，正阴性结果一律同样处理，不修改导航动作 |
| 首次标定尝试中断 | 三组完整 2-MON 标定 | attempt1 在 TEEsavR23oF/0 第108次决策因记录器把脱困点当查询候选而失败；控制器随后终止另卡。整次尝试保留并排除于拟合，两场景从头重收 | 含 1 个完整 episode 和两个未完成前缀；按记录器版本排除整次尝试，未按成功/失败挑选。修复后增加两个记录器测试，18 项通过，219 次旧模式回归仍一致 |
